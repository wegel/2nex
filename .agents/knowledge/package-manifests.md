# Package Manifests

This note absorbed the durable facts from the former
`.claude/agent_docs/working-on-package-manifests.md` before Nex removed the
stale Claude setup. The current manifests, `.agents/MANIFESTS_CODE_STYLE.md`,
and `.agents/TESTING.md` override old versions or commands recorded here.

## Manifest Shape

A package manifest normally contains these top-level keys:

- `package`: schema, name, slug, namespace, version, description, homepage, and
  checksum.
- `sources`: remote archives and local files with sha256 values.
- `dependencies`: named store refs that the build root checks out.
- `build`: environment, profile, and shell script.
- `bundles`: named groups that point at outputs.
- `outputs`: file lists, usually generated by the builder.
- `resolution`: dependency file mapping, generated by the builder.

Build-time dependencies are explicit and manual. Add compilers, headers,
configure helpers, language interpreters, and build tools to `dependencies`
when the package script needs them. The builder does not pull these inputs
automatically from the final installed files because they can affect the output
without appearing in the output. A build root receives only the build inputs
named by the manifest and their recorded closures.

Runtime library dependencies are automatic after install. `--compute-deps`
inspects ELF files and generates library `needs` metadata from the installed
output. Scripts and plugin loaders still need manual runtime `needs` because
ELF scanning cannot see an interpreter command line, a shell helper, or a
module loaded only at runtime.

Use `placeholder` for a new remote source sha256 when the real value is not
known yet. The build will fetch the source and report the correct hash.

When a manifest uses a local file source, update that source hash after every
file edit:

```bash
sha256sum path/to/local/source
```

The builder rejects a stale local source hash with a SHA256 mismatch.

## Outputs And Bundles

Define `dev` and `full` bundles by hand when the package has those concepts.
Keep bundle names aligned with output categories such as `bin`, `lib`, `dev`,
`man`, and `doc`.

Use `--generate-outputs` and `--compute-deps` for normal manifests. Do not
hand-write large file lists or the dependency resolution map when the builder
can compute them.

Some packages need curated output names. The kernel manifest uses names such as
`boot`, `modules-meta`, `drv-eth-intel`, and `drv-gpu-amd`. The builder must
preserve existing output names when it regenerates file lists for those
manifests.

## Build Script Patterns

Autotools packages usually unpack into `${WORK_DIR}`, run configure with
`--prefix=/usr`, install into `${OUT_DIR}`, strip installed executables when
safe, make static archives deterministic, and normalize timestamps.

Meson packages usually run `meson setup build --prefix=/usr
--buildtype=release`, build with `ninja -C build`, and install with
`DESTDIR="${OUT_DIR}" ninja -C build install`.

Use this timestamp normalizer in deterministic package scripts:

```bash
find "${OUT_DIR}" -exec touch -d "2024-01-01T00:00:00+00:00" {} \;
```

Use deterministic archives when the package installs `.a` files:

```bash
find "${OUT_DIR}" -name '*.a' -exec objcopy --enable-deterministic-archives {} \; 2>/dev/null || true
```

For Nvidia no-compat32 runfiles, do not execute the makeself stub in the build
script. Read the `skip=` header value, then pipe the embedded zstd payload
through `tail`, `zstd -d`, and `tar --no-same-owner` into `${WORK_DIR}`:

```bash
mkdir -p "${WORK_DIR}/nvidia"
nvidia_skip="$(awk -F= '/^skip=/{print $2; exit}' "/${SOURCE_nvidia}")"
tail -n +"${nvidia_skip}" "/${SOURCE_nvidia}" \
  | zstd -d \
  | tar --no-same-owner -xf - -C "${WORK_DIR}/nvidia"
```

Evidence: Nvidia's makeself wrapper calls `cksum` and plain `tar xvf -`.
The standard Nex build root did not provide `cksum`, and plain tar extraction
hit namespace metadata problems. Both Nvidia 580 and 595.84 package manifests
passed strict two-pass builds after they extracted the payload directly.

Nvidia external-platform JSON files name stable `.so.1` library names. The
Nvidia runtime output must install those symlinks next to the versioned
libraries.

Evidence: `desktop-vwl-nvidia-580` smoke inspection found
`/usr/share/egl/egl_external_platform.d/15_nvidia_gbm.json` names
`libnvidia-egl-gbm.so.1`; the package output had to add
`libnvidia-egl-gbm.so.1 -> libnvidia-egl-gbm.so.1.1.3` and similar stable
symlinks before the runtime bundle was complete.

Package outputs can declare runtime capabilities with `provides:`. Generated
output refreshes keep that metadata and also keep `capability_files:` filters.
For graphics packages, Mesa provides `graphics.egl`, `graphics.gles`, and
`graphics.gbm`; Nvidia runtime bundles provide `graphics.egl` and
`graphics.gles`; Mesa remains the GBM provider for the current Nvidia desktop
assemblies.

## Troubleshooting

If LTO breaks a package link, remove `-flto=auto` from the build flags in that
package script:

```bash
CFLAGS=${CFLAGS/-flto=auto/}
CXXFLAGS=${CXXFLAGS/-flto=auto/}
LDFLAGS=${LDFLAGS/-flto=auto/}
```

If configure says the C compiler cannot create executables, inspect
`.nex/tmp/build_rootfs_*/nex/work/config.log`. Common fixes include adding
`zlib` for `libz.so.1`, or adding missing tools such as `diffutils` and `file`.

If configure says the C preprocessor fails a sanity check, add
`linux-headers` and pass `CPP=cpp` to configure.

If a C++ package links without the standard C++ library, add this before
configure or Meson:

```bash
export LDFLAGS="${LDFLAGS} -lstdc++"
```

Build scripts must not mutate dependency roots such as `/usr/lib`, even for
compatibility symlinks or generated metadata. Create writable overlays under
`${WORK_DIR}` and point upstream build variables at those paths.

Evidence: Chromium's strict build failed when the script tried to create
`/usr/lib/clang/22`, `/usr/lib/libffi_pic.a`, and
`/usr/lib/pkgconfig/nss.pc`. The manifest now creates those compatibility
files under `${WORK_DIR}/clang-base`, `${WORK_DIR}/libffi-pic`, and
`${WORK_DIR}/pkgconfig`, then sets `clang_base_path`, `LIBRARY_PATH`, and
`PKG_CONFIG_PATH`.

ELF scanning cannot see libraries that a program opens through a plugin loader.
Declare those runtime files manually in `needs` and map them in `resolution`.

Evidence: Chromium started under Wayland but NSS failed with
`libsoftokn3.so: cannot open shared object file`. The Chromium manifest now
declares NSS plugin files from the `nss` package, including `libfreebl3.so`,
`libfreeblpriv3.so`, `libnssckbi.so`, `libnsssysinit.so`,
`libsoftokn3.so`, and `libsqlite3.so`.

Chromium graphical launches can need `chrome_crashpad_handler` beside the
browser binary. Install it when the Chromium build produces it and include it
in the `bin` output.

Evidence: the first graphical Chromium smoke after the virtio KMS fix logged
that `/usr/lib/chromium/chrome_crashpad_handler` was missing. After the
manifest installed that helper, the QEMU graphical smoke reached the page and
passed the screenshot pixel check.

If a package runs Python tools during the build, add `python3`. Some Python
helpers may also need package-specific Python modules.

Some GNOME Meson packages need Python GI even when the package disables GIR
output. Add `pygobject` and `gobject-introspection` when configure or a build
helper imports `gi`.

Evidence: `libgweather` 4.4.4 ran
`build-aux/meson/gen_locations_variant.py`, Meson reported `Program python3
(gi) found: YES`, and the manifest passed `-Dintrospection=false` and
`-Denable_vala=false`. The strict build passed only after the manifest listed
the Python GI providers as build inputs.

Meson packages must manually list pkg-config transitive build requirements
when configure asks for them. Runtime dependency scanning does not make those
`.pc` files appear in `PKG_CONFIG_PATH`.

Evidence: `geocode-glib` checked out `libsoup3` and `json-glib`, but Meson
could not produce cflags for `libsoup-3.0` until the manifest added `sqlite3`,
`libpsl`, `brotli`, and `nghttp2` build inputs.

When a Wayland or GTK4 package fails because `cairo.pc`, `epoxy.pc`, or
`gtk4.pc` asks pkg-config for X11, inspect the provider's enabled backends
before adding X11 to the consumer. Cairo can export Xlib/XCB requirements when
its X surfaces are enabled, and libepoxy can export `Requires.private: x11`
when GLX/X11 support is enabled. Wayland defaults should keep those provider
features disabled unless the package truly needs an X11 surface.

Evidence: Loupe 49.2 used `-Dx11=disabled`, but earlier work added X11
providers after `dependency('gtk4')` failed. On 2026-06-30, rebuilding
`cairo` with `-Dxcb=disabled -Dxlib=disabled -Dxlib-xcb=disabled` and
`libepoxy` with `-Dglx=no -Degl=yes -Dx11=false` made `slurp`, `swaybg`,
`swaylock`, `fuzzel`, `librsvg`, GTK4, libadwaita, and Loupe build
reproducibly without X11 build inputs. Loupe's Meson log reported
`Dependency gtk4-x11 skipped: feature x11 disabled`.

Some GL builds need X11 headers even when the app disables its own X11 display
backend. GLX headers can include `X11/Xlib.h` through `GL/glx.h`, so add the
normal X11 header providers when the compile fails there.

Evidence: Looking Glass B7 built with `ENABLE_X11=OFF`, but
`client/src/gl_dynprocs.c` included `GL/glx.h`, which included `X11/Xlib.h`.
The package passed after adding `xorgproto`, `libx11`, `libxcb`, `libxau`, and
`libxdmcp`.

CMake shader or code-generation rules may call simple Unix tools directly.
Add the tool package as a build dependency when the build rule invokes it.

Evidence: Looking Glass B7's EGL shader generation ran
`grep ^#define ...` and failed with `/bin/sh: line 1: grep: command not found`
until the manifest added `pkg/cli/text/grep`.

Rust packages that use `cargo_lock` vendor tarballs need `gzip` in the build
root when the generated vendor input is a `.tar.gz`.

Evidence: the first strict Loupe build failed while extracting
`${SOURCE_vendor}` with `tar (child): gzip: Cannot exec`. Adding the `gzip`
dev bundle supplied the decompressor.

If a package installs a script, ELF scanning will not see its interpreter or
subcommands. Preserve or add manual `needs` entries for files such as
`/usr/bin/python3`, `/usr/bin/perl`, or `/usr/bin/ssh`, then smoke the script
from a checked-out package root that contains those runtime package refs.

Evidence: `dool` needed a manual Python need, and `mosh` needed manual Perl
and OpenSSH needs after its wrapper shebang was rewritten to
`#!/usr/bin/perl`.

Shell wrapper scripts need the same manual treatment. If a script has
`#!/bin/sh`, add `needs: /usr/bin/sh` to the script output and add
`/usr/bin/sh: bash` to `resolution`.

Evidence: VLC installed `cvlc`, `nvlc`, and `rvlc` with `#!/bin/sh`. A package
smoke root could not execute those wrappers until
`pkg/apps/multimedia/vlc.yaml` added manual `/usr/bin/sh` needs and resolved
that path to Bash.

Python application wrappers should use an interpreter path that exists in the
checked-out root and should add their package-local module paths before they
import application code.

Evidence: `virt-manager` installed wrappers with `#!/usr/bin/env python3`,
but the smoke root had `/usr/bin/python3` and no `/usr/bin/env`, so execution
failed with `No such file or directory`. Rewriting the wrappers to
`#!/usr/bin/python3` fixed interpreter lookup. The assembled `desktop-vwl`
root then exposed `/usr/bin/virt-manager` as a symlink into
`/nex/pkg/apps/virt/virt-manager/...`; adding a wrapper shim based on
`os.path.realpath(__file__)` inserted the capsule's
`usr/lib/python3.12/site-packages` path and let the wrapper import `gi`,
`requests`, `libvirt`, `virtinst`, and `virtManager.virtmanager`.

This also applies to Python command-line build tools that install modules in
their own package tree. Do not rely on the merged
`/usr/lib/python3.12/site-packages` path in an assembly, because the Python
interpreter package can have a baked `sys.path` under its own `/nex/pkg`
location. Wrap the command so it resolves `os.path.realpath(__file__)`,
prepends the package-local `usr/lib/python3.12/site-packages`, and then imports
the tool.

Evidence: after `desktop-dev` switched Meson from `outputs/bin` to
`bundles/dev`, `meson --version` still failed with `ModuleNotFoundError:
No module named 'mesonbuild'`. Python's `sys.path` inside the root listed the
Python package path under `/nex/pkg/dev/lang/python3/...`, while `mesonbuild`
existed under `/nex/pkg/core/toolchain/meson/...`. Replacing Meson's launcher
with a package-local `sys.path` wrapper made
`unshare --root .nex/tmp/meson-smoke /usr/lib/ld-linux-x86-64.so.2
/usr/bin/python3.12 /usr/bin/meson --version` print `1.6.1`.

For Python runtime `needs`, a package-directory import such as
`/usr/lib/python3.12/site-packages/requests/__init__.py` now causes the
assembly capsule flattener to copy the provider's whole `requests/` directory.
Top-level module files such as `libvirt.py` still need any compiled extension
modules or shared libraries named separately.

Evidence: a package-root `virt-manager` smoke passed because it checked out
whole provider refs, but an assembled `desktop-vwl` smoke failed first on
missing `gi/_gi...so` and later on missing `urllib3.exceptions`. After the
flattener copied all provider manifest files below the referenced Python
package directory, `desktop-vwl` flattened 343 runtime files into the
`virt-manager` capsule and the assembled-root smoke imported the full
Python/GI stack.

GObject-introspection typelibs need manual runtime `needs` for imported
typelibs because ELF scanning cannot infer GI namespace imports.

Evidence: `libosinfo` and `libvirt-glib` smokes had their own typelibs, but
Python GI imports failed on missing `libxml2-2.0.typelib` and
`GLib-2.0.typelib` until the manifests recorded those imported typelib files.
GTK-VNC and VTE smokes also needed the active `at-spi2-core` package to own the
matching `Atk-1.0.typelib` and `Atspi-2.0.typelib` for the loaded GTK stack.

If a package script changes directory and then reads a second source archive,
use an absolute chroot path such as `/./${SOURCE_name}`. Source variables are
relative to the chroot launch directory.

Evidence: the first `openbsd-netcat` build failed after `cd ${WORK_DIR}` and
then `tar -xf ${SOURCE_debian}`. Using `/./${SOURCE_debian}` fixed the lookup.

Package smoke roots that do not include the system assembly's `/lib64` link may
need direct dynamic-loader invocation:

```bash
unshare --root "$tmpdir" /usr/lib/ld-linux-x86-64.so.2 --library-path /usr/lib /usr/bin/<cmd> --version
```

When a package smoke needs to execute scripts with `#!/bin/sh` or ELF files
that name `/lib64/ld-linux-x86-64.so.2`, add assembly-style symlinks inside
the disposable smoke root:

```bash
ln -s usr/bin "$root/bin"
mkdir -p "$root/lib64"
ln -s ../usr/lib/ld-linux-x86-64.so.2 "$root/lib64/ld-linux-x86-64.so.2"
```

Evidence: the VLC package smoke needed those links before `vlc`, `cvlc`,
`nvlc`, and `rvlc` could run in the checked-out package root. The assembled
`desktop-vwl` root already had the loader shim and `/usr/bin/sh`.

Host-side compile smokes against a checked-out package root may need
`-Wl,-rpath-link,<root>/usr/lib` so the host linker can find indirect
libraries in that root.

Evidence: a tiny `libgweather` consumer compiled with `gweather4.pc`, but the
link failed until the command added `-Wl,-rpath-link,$root_abs/usr/lib` for
indirect `libxml2` and `geocode-glib` libraries.

Full system checkouts normally provide the public links, so prefer a checked
system smoke after assembly work.

Qt platform plugins are runtime files loaded with `dlopen`, so ELF scanning
does not discover them from the main executable. For a Qt GUI app that must run
from a `nex_structure` app capsule, copy the required platform plugins into
the package, record manual `needs` and `resolution` entries for those plugin
files, and wrap the real binary with a script that sets `QT_PLUGIN_PATH` to the
package-local plugin directory.

Evidence: SQLite Browser worked in a flat package smoke root but failed from a
checked-out `desktop-dev` root with `qt.qpa.plugin: Could not find the Qt
platform plugin "offscreen" in ""`. The package now installs
`/usr/libexec/sqlitebrowser/sqlitebrowser`, copies `libqminimal.so` and
`libqoffscreen.so`, sets `QT_PLUGIN_PATH` in `/usr/bin/sqlitebrowser`, and the
package smoke runs `sqlitebrowser --version` with `QT_QPA_PLATFORM=offscreen`.

The current `qt6-base` package provides the minimal and offscreen platform
plugins used by the SQLite Browser smoke, but it does not provide common
desktop Wayland or xcb platform plugins. A true Qt desktop GUI on Wayland or
X11 needs a future Qt Wayland package or an xcb/wayland platform plugin stack.

Evidence: the SQLite Browser package could copy `libqminimal.so` and
`libqoffscreen.so` from `qt6-base`, but no `libqwayland-generic.so` or xcb
platform plugin was available in the Qt platform plugin directory. The wrapper
falls back from `QT_QPA_PLATFORM=wayland` to `minimal` when no Wayland plugin
exists.

Minimal smoke roots may not contain `/dev/null`. Avoid wrapper redirections to
`/dev/null` unless the smoke root creates device nodes or the checked system
root proves they exist.

Evidence: a SQLite Browser package-root smoke printed `/dev/null: No such file
or directory` while the wrapper ran `readlink "$script" 2>/dev/null`. Removing
that redirection kept the smoke quiet.

VLC 3.0.23 builds against the repo FFmpeg 8 package when the manifest disables
the old optional stacks that are not present. VLC 3.0.21 did not compile
against that FFmpeg version with the tested feature set.

Evidence: VLC 3.0.21 failed on removed `AVCodecContext` fields and old FFmpeg
symbols. VLC 3.0.23 built reproducibly with Qt, X, Wayland, and many optional
plugins disabled, while keeping command, ncurses, ALSA, FFmpeg, and plugin
support.

VLC's generated `/usr/lib/vlc/plugins/plugins.dat` is not reproducible. Delete
it after install and smoke the package with `/usr/lib/vlc/vlc-cache-gen` so the
installed plugin shared objects still prove usable.

Evidence: comparing the first VLC raw store checkout against the second split
output, after removing output-category prefixes, found 728 matching paths and
exactly one changed file: `plugins.dat`. Deleting it made the strict VLC build
pass with checksum
`f0721b8de57797bcf6d7a04cbba5797d9fc034a24bc7f9744d4ccbd059c4a3c2`, and
package plus assembled-root smokes regenerated the cache from 238 plugin
shared objects.

The repo already has a source Chromium package at `pkg/apps/web/chromium.yaml`.
Use it as the supported browser package unless a plan specifically targets a
different browser stack.

Evidence: `nex check pkg/apps/web/chromium.yaml` passes, the store has
`x86_64/pkg/apps/web/chromium/143.0.7499.169/bundles/full`,
`nex resolve chromium --verbose` returns a 55-ref runtime closure, and package
plus assembled-root smokes ran `chromium --version` and
`chromedriver --version`.

Vimb needs WebKitGTK first. This repo currently lacks Vimb, WebKitGTK, WPE, and
JavaScriptCore manifests.

Evidence: `rg --files pkg` found GTK, libsoup3, and Chromium manifests, but no
WebKitGTK, WPE, JavaScriptCore, or Vimb stack.

## UAPI Configuration Parser Patches

Before moving a package default from `/etc`, find every reader, reload path,
file watch, explicit override, and drop-in parser in the pinned source. One
manifest path can feed several independent readers. Keep command-line,
environment, and per-user overrides ahead of the system tiers. Tests must call
the built readers with distinct files under `/etc`, `/run`, and `/usr`; an
install-path assertion cannot prove the lookup order.

Evidence: BlueZ 5.85 reads `input.conf` in two places and reads `main.conf`
and `network.conf` in separate code. PulseAudio 17.0 sends four main files
through two helpers and merges only two structured drop-in families. OpenSSH
9.9p1 reparses saved server text for `Match` blocks and preserves its argument
vector on SIGHUP. Glibc 2.39 caches nsswitch metadata and registers that path
with nscd. EP011 patched and exercised all of those paths.

A local patch source does not add the `patch` command to a build root. List
the repository's patch bundle under `dependencies`, hash the local patch, and
apply it with `patch --batch --fuzz=0` so stale context fails loudly.

OpenSSH uses first-obtained-value parsing. A standard drop-in selector must
remove lower-tier basenames shadowed by higher tiers, then feed surviving
files in descending lexical order so lexically later names keep priority.
Keep arbitrary explicit `Include` paths unchanged. Pre-install tests must also
provide a temporary account database, `/var/lib/sshd`, a throwaway host key,
and the freshly built `sshd-session` path before starting `sshd`.

Glibc treats empty and missing files as equivalent in its generic file-change
cache. A live UAPI selector must store the chosen tier as well as file
metadata, and nscd must watch all candidate paths. Test appearance, edits, and
removal in one long-lived process inside a private chroot. Never change the
workstation's `/etc` for a package test.

PulseAudio's installed daemon uses `DT_RPATH` for `/usr/lib/pulseaudio`.
`LD_LIBRARY_PATH` alone may load an older host library during a split-output
smoke. Call the packaged dynamic loader with `--inhibit-rpath ''` and an
explicit `--library-path`, or test from a merged package root.

The Freedesktop Autostart Specification makes `/etc/xdg/autostart` an
externally governed package path, not an ordinary vendor-default directory.
It tells desktop sessions to scan `autostart` below `XDG_CONFIG_HOME` and
each `XDG_CONFIG_DIRS` entry; the Base Directory Specification defaults the
system list to `/etc/xdg`. Keep upstream system autostart entries there so
ordinary desktops find them, and let higher-priority XDG entries override or
disable the same basename.

Evidence: Gnome Keyring 50.0 installs its PKCS#11 and Secrets entries there,

An installed configuration file can be documentation even when upstream
places it below `/etc`. Read both its contents and its consumer before moving

`/usr/share/doc/<package>/examples`, and keep the real administrator path in

Evidence: p11-kit 0.25.5 says its `pkcs11.conf.example` has no effect until an

`d8524f53a7e4fc14400f74404828eff6059072c1457baab610eac5dc5ba889a6`
and
`9829fa1b95f94bc0a3185e52c6b618b5b1d5e9eb6a26b51edbdd0b5536c79047`.

P11-kit accepts colon-separated trust input paths and gives the first path
the highest priority. Configure `/etc/pki/trust`, `/run/pki/trust`, and

administrator policy, transient policy, and package anchors. An
administrator blocklist entry can suppress the same certificate in a lower
vendor source.

CA Certificates installs Mozilla's anchors below

Shell-script output needs must name commands that ELF scanning cannot find.
The CA updater names its shell, Coreutils commands, p11-kit `trust`
executable, and `/usr/share/p11-kit/modules/p11-kit-trust.module`. That last

rather than through an ELF dependency. P11-kit's `dev` and `runtime` bundles

A Nex structured assembly must select p11-kit's runtime bundle when the live
root needs `/usr/bin/trust`. A dependency can copy the command into another
package's capsule without making a public command link in the assembled root.
Likewise, `systemctl --root` does not model a unit that Nex stages through its
factory `/etc`; boot the system and inspect the live unit and artifact.

`trust extract --format=pem-directory-hash` writes its target directory as
mode `0555`. A package test must restore owner write permission or remove that
disposable directory before Nex starts its second reproducibility build;
otherwise the build runner cannot clean the retained work root.

## Bootstrap roots

Bootstrap sysroots should contain only inputs that a concrete next phase
needs. Nex's phase-zero toolchain needs no `/etc/rpc`; phase-one Glibc needs no
`/etc/nsswitch.conf`, `/etc/rpc`, or `/etc/ld.so.cache`. Both loaders find the
bootstrap libraries below `/usr/lib`. Test each cleaned sysroot by compiling,
linking, and running a program with its new compiler, sysroot, and loader, and
build `pkg/bootstrap/phase1/test.yaml` as a separate phase-zero consumer.
Phase zero sets `stable_checksum: false`, so it needs this downstream proof
because `--check` performs only one build for that manifest.

## Host accounts

A reusable package must not create `/etc/passwd` or `/etc/group` records.
Assemblies choose initial users, groups, numeric IDs, home directories, and
shells, then place those records in their factory tree for first-boot seeding.
Test the finished root by seeding a disposable `/etc` and calling its packaged
NSS consumer, such as `id`, rather than checking file text alone.

## Libvirt configuration and objects

Libvirt 11.0.0 has fifteen privileged main-file readers across its clients,
daemons, network and QEMU drivers, lock manager, authentication, and login
shell. A shared private helper can select one complete file from
`/etc/libvirt`, `/run/libvirt`, then `/usr/lib/libvirt`. Keep explicit daemon
`--config` arguments and unprivileged XDG paths unchanged. Use literal
`/run/libvirt` for the transient tier; Libvirt's configured `RUNSTATEDIR`
expands to `/var/run`, and a minimal root need not provide that compatibility
link.

The nwfilter and virtual-network XML files are different: Libvirt imports and
mutates them as machine objects. Store the upstream copies as package
templates below `/usr/share/libvirt/initial-state`, then let an assembly choose
whether to seed them into writable host state. The package's four logrotate
fragments and OpenSSH proxy fragment remain at their standard integration
paths.

## Linux-PAM system policy

Linux-PAM 1.7.1 has separate readers for service policy and the access,
faillock, group, limits, namespace, pwhistory, time, environment, and shells
module files. Meson's vendor-directory option changes install paths but does
not add every missing reader tier. Patch each reader before moving package
files, keep explicit module arguments exact, and test the installed modules.

The generic package patch selects whole files from `/etc`, `/run`, then
`/usr/lib`, and merges supported drop-in directories by basename in the same
priority. Empty higher files mask lower policy. The manifest installs ten
package files below `/usr`, and its strict build checksum is
`a1cd20aac485d045fd8412b8a568a102293ea8257892bc5b688aaf270bfd9a20`.

PipeWire's `25-pw-rlimits.conf` is a package default for PAM's limits module,
so install it below `/usr/lib/security/limits.d` after that reader supports the
vendor tier. On a build host whose hard real-time priority and nice limits are
zero, applying the real fragment returns a PAM denial even though PAM applies
its 4 GiB memory-lock request. Assert both facts so the test proves the actual
file was parsed. PipeWire's strict checksum is
`39dcd9b0b389cba437384c51390d1367fe36af49834f9457181ebae588bf0af0`.

## Remaining package `/etc` integration points

Count package-owned `/etc` files from declared output paths, not every literal
path in a build script. Build scripts may create temporary policy files only
to test a reader. On 2026-08-15, this command found 15 declared paths in seven
manifests:

    rtk proxy rg --glob '*.yaml' '^\s*- path: /etc(?:/|$)' pkg

At EP012's starting revision, `855f476^`, the same declared-output scan found
289 paths in 31 manifests. CA Certificates accounted for 150 generated paths,
so the other package-owned paths fell from 139 to 15. This measures package
policy, not the complete live `/etc`; assemblies and boot services still
create host state and generated compatibility databases.

Every remaining path serves an external integration contract:

- Gnome Keyring and AT-SPI2 retain three files below
  `/etc/xdg/autostart`; desktop sessions scan that path through the XDG Base
  Directory and Autostart specifications.
- Bash Completion retains `/etc/bash_completion`, its compatibility entry
  below `/etc/bash_completion.d`, and its profile hook. VTE retains two
  profile hooks. Existing shells and system profiles load these five paths.
- Libvirt retains four files below `/etc/logrotate.d` and its OpenSSH proxy
  fragment below `/etc/ssh/ssh_config.d`; the matching external tools scan
  those directories.
- Both Nvidia driver manifests retain `/etc/OpenCL/vendors/nvidia.icd`;
  Khronos fixes that Linux ICD discovery directory.

These paths need an assembly factory fallback on an immutable host. Do not
move them into a package-private vendor path unless the external loader adds
and documents that path.
